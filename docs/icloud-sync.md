# iCloud 同步范围

本次检查依据应用代码；没有用两个已签名、登录同一 Apple ID 的设备完成云端往返测试。

| 内容 | 通道与范围 |
| --- | --- |
| 课表与课程 | SwiftData / CloudKit：课表名称、学期名称、当前课表标记；课程名称、教师、地点、周次、星期、节次、时长、颜色。独立于会员“设置与图片同步”开关。 |
| 教务账号密码 | iCloud 钥匙串；系统须允许钥匙串同步。登录后另存本地备用。 |
| 应用偏好 | 会员开关控制：周起始日、显示时间范围、网格和时间标尺、当前时间线、全天事件、时间间隔、课程与背景透明度、背景开关、学期开始日、课程与考试提醒偏好、假期跳过提醒、时间轴模式、玻璃效果、茶馆横幅与触感。 |
| 背景图、头像 | 会员开关控制的新图片同步：Drive 保存图片，KVS 保存文件引用；头像按教务账号区分。旧版本头像文件保留兼容恢复。 |
| 电费房间 | 会员开关控制：保存的区域、楼栋、房间、显示名与配置 ID。删除配置同样传播。 |

系统通知权限、系统日历授权及导出开关、实时活动开关、小组件实例配置仍由每台设备独立管理。会员资格通过 StoreKit 校验，不作为普通设置同步。成绩、考试、电费历史和其他接口缓存不复制到 iCloud；茶馆数据由其服务端同步，SwiftData 茶馆缓存留在本机。

## 修复的问题

- 背景原先只同步开关和透明度，图片本身没有上传。
- 电费房间配置原先只写入本机 UserDefaults。
- 任意 UserDefaults 变化都会把所有偏好重写入云端；改为比较本机已观察的值，只发送变更字段。拉取云端时保留尚未处理的本地修改，抑制延迟通知引起的回写。
- 新设备不把 AppSettings 的内建默认值整包上传；老设备首次迁移只补充明确持久化、云端尚不存在的设置。
- 图片使用不可变文件引用与协调读写，等待下载时保留本地图片，通过云文件更新事件重试；文件内容校验后才替换本地引用。清除图片使用删除标记，避免旧设备又恢复已清除的图片。
- 同步开关与会员变化在应用根节点处理；会员校验后再启动同步，避免依赖设置页是否打开。
- CloudKit 存储初始化失败后的本机/临时存储回退会在设置页提示；“已配置 CloudKit”不代表云端已上传完成。

## 验证

`CCZUHelperTests/ICloudSettingsSyncTests.swift` 覆盖双设备不同字段修改、远端更新不回写、新设备默认值、离线修改、未知字段，以及图片引用、内容校验、失败时保留原图片。测试使用隔离目录，不访问真实 iCloud。

Apple 接口依据：[KVS 同步](https://developer.apple.com/documentation/foundation/nsubiquitouskeyvaluestore/synchronize())、[iCloud 文档同步](https://developer.apple.com/documentation/uikit/synchronizing-documents-in-the-icloud-environment)。`synchronize()` 不能当作“所有云端数据已到达”的完成回调。
