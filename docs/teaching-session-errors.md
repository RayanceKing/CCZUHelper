# 教务登录恢复与错误展示

## 原因

- 成绩、绩点、考试、个人资料和课程评价在有缓存时忽略刷新失败，用户只能看到旧资料。
- 多个页面各自执行 SSO 和教务登录，没有共享登录恢复流程。启动恢复也建立了另外的会话。
- CCZUKit 1.1.3 未统一检查 HTTP / 业务状态，并把 `message` 解码失败转换为空数组。异常可能被误认为“没有数据”，甚至写回缓存。
- 培养方案的刷新会读 SDK 内存或磁盘缓存，未必访问服务器。

## 当前行为

1. 启动恢复、查询和提交共用当前账号的会话；并发登录合并为一次。
2. 收到 HTTP 401 或明确的登录失效业务响应时，重新登录并重试**该 HTTP 请求一次**。重新登录仍失败则向调用方抛错。
3. 普通权限错误、服务器错误、网络失败和解析异常直接报错。业务错误保留错误码和服务端原因。取消请求不显示错误。
4. 有缓存时保留内容并显示 banner，注明本次更新未完成；没有缓存时显示可重试的错误页。登录错误提供登录入口。登录、导入及维护错误采用页面内提示。
5. 成功后清除错误并更新缓存；错误响应不能清空缓存。启动自动恢复失败也显示 banner，不删除存储在 Keychain 的密码。
6. 选课、退课、评价只在明确认证拒绝时重试单条请求；不重放整个提交流程，不因网络错误自动重复提交。批量评价逐条保存已成功状态。
7. 用户手动输入的账号先独立验证，成功后才替换共享会话；指定账号的密码缺失时，不选择另一个 Keychain 账号。

## 依赖与验证

本改动将 CCZUKit 1.1.3（504d5ca061a34a187dcd1261f09bb64febc93502）作为仓库内源码依赖，保留原始 GPL-3.0 许可证。会话恢复需要底层响应校验和请求级重试同时生效，不能只修改应用层。

库相对 1.1.3 的实际修复见 `Packages/CCZUKit/LOCAL_CHANGES.md`。内嵌 SDK 会增加本 PR 文件数和后续依赖维护成本；这属于本 PR 需要维护者评估的取舍。

`swift test --package-path Packages/CCZUKit --filter TeachingSessionTests` 使用模拟响应验证登录恢复、并发合并、错误传播、取消和提交重试，不访问真实教务账号。

手动验收：已有缓存时断网刷新应保留内容并显示错误；重新联网重试后更新并清除提示。没有缓存时显示可重试的错误页。取消刷新不弹出错误。
